# 운영 분류체계 문서 (taxonomy.md) 권장 템플릿

팀이 문서로 확정한 운영 분류체계를 **팀 루트(profile.json 옆)에 `taxonomy.md`로** 저장하면, 다음 보고서부터 분류체계를 새로 도출하지 않고 이 문서의 유형으로 각 건을 배정한다.

- 이 형식은 **권장이지 강제가 아니다.** 읽는 주체가 LLM 에이전트라 팀 위키를 그대로 붙여 넣어도 동작한다. 다만 유형마다 정의·키워드·예시가 있을수록 배정이 정확해진다.
- 유형은 **6~10개**, 이름은 팀에서 실제로 쓰는 말을 권장한다.
- 데이터에 분류 코드가 이미 있는 팀(coded)에서는 이 문서가 집계에 쓰이지 않고, 시사점 작성 시 유형 정의·용어 참고로만 쓰인다.

아래 구획선 이후가 템플릿 본문이다. 스킬이 사용자의 체계를 이 형식으로 변환할 때, 그리고 도출된 제안을 확정본으로 저장할 때 이 구조를 따른다.

# <팀명> 운영 분류체계

확정일: <YYYY-MM-DD> · 근거: <팀 위키 / 2026-07 보고서 제안 확정 등>

## A. 계정·권한 관리

- 정의: 계정 생성·비활성화·권한 부여 및 회수. 비밀번호 초기화 포함.
- 키워드: 계정, 비밀번호, 권한, 초기화
- 예시: 신규 입사자 계정 생성 요청 / 퇴사자 계정 비활성화
- 중분류(선택): 입·퇴사 처리, 인증 관리, 권한 변경

## B. 오류 조치

- 정의: 기능이 의도대로 동작하지 않는 상태의 원인 파악과 복구.
- 키워드: 오류, 장애, 안 됨, 실패
- 예시: 전자결재 상신 시 오류 발생 / 메일 수신 안 됨

## 경계 규칙 (선택)

두 유형에 걸치는 요청의 우선순위. 배정 일관성을 만드는 핵심이다.

- 오류 조치와 사용 안내가 함께면 → 오류 조치
- 설정 변경을 동반한 권한 요청이면 → 계정·권한 관리
