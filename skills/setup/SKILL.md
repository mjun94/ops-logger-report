# 팀 프로필 셋업

데이터 경로: **$ARGUMENTS** (비어 있으면 경로를 물어본다)

새 팀이 처음 한 번만 하는 작업이다. **사용자는 경로만 입력한다.** 나머지는 데이터에서 추론하고, 추론할 수 없는 것만 한 번에 묻는다.

## 1. 자동 진단·생성

```bash
python3 "${CLAUDE_SKILL_DIR}/../monthly/scripts/init_profile.py" <데이터.json>
```

데이터 파일과 같은 폴더의 상위(관례상 팀 작업 폴더)에 만들려면 `--out-dir`를 준다. 기본은 현재 위치다.

이 스크립트가 자동으로 판정하는 것:

- **필드 매핑** — 요청일·처리시작/완료·채널·담당자·요청조직·부서·요청자명·원문 필드를 이름 후보로 매칭
- **UTC 저장 필드** — 값이 `Z`/`+00:00`으로 끝나는 시각 필드
- **채널 목록** — 실제 값에서 추출
- **자사명** — 접수 조직과 원요청 조직이 다른 건에서 가장 흔한 접수 주체
- **분류체계 성숙도** — 코드 커버리지로 `coded`/`partial`/`none` 판정
- **추출 기준 위험** — 로깅일 기준 추출이면 과소집계 경고

## 2. 결과 보고 & 확인

스크립트 출력을 사용자에게 그대로 요약해 보여준다. 특히 이 세 가지는 꼭 짚는다.

- 처리시간 산출 가능 여부 (`started_at` 유무) — 불가하면 추출 쿼리에 추가를 권한다
- 요청자 집중도 집계 단위 (요청자명 유무)
- 분류체계 성숙도 — `none`이면 첫 보고서에서 데이터 기반으로 도출·제안한다고 알린다

매핑이 틀린 필드가 있으면 사용자에게 확인받아 `profile.json`을 고친다.

## 3. TODO 채우기 (한 번에 질문)

`profile.json`의 `TODO` 항목만 물어 채운다. 추측해서 채우지 말 것.

| 항목 | 질문 |
|---|---|
| `team` / `org` | 팀명·조직명 (표지·사이드바에 표기) |
| `report_title` | 보고서 제목 (예: "Ops Logger 기반 서비스 운영 가시화") |
| `short_title` | 사이드바·파일명에 쓸 짧은 이름 (예: "Ops Logger") |
| `org_dimension_label` | 05 슬라이드 제목 — "계열사별" / "고객사별" / "부서별" 중 무엇인지 |
| `insight_frame` | 이 팀 보고서에서 매월 유지할 해석 관점 (없으면 첫 보고서 후 채워도 된다) |
| `taxonomy_map` | 분류 코드가 있으면 코드 → 유형명 매핑 |
| `watch_metrics` | 매월 추적할 지표 (예: 비밀번호 초기화 건수) — 없으면 생략 |

## 4. 과거 보고서가 있으면 베이스라인 채우기

과거 월간 보고서가 있으면 그 **공표 수치**를 `baselines.json`에 옮긴다. 집계로 재계산하지 않는다. 이미 나간 숫자가 정본이다.

스키마는 [../monthly/references/schemas.md](../monthly/references/schemas.md), 예시는 플러그인의 `examples/baselines.groupware.json` 참조.

과거 보고서가 없으면 그대로 둔다. 첫 보고서는 비교 없이 생성되고, 이후 매월 자동으로 누적된다.

## 5. 검증 & 안내

```bash
python3 "${CLAUDE_SKILL_DIR}/../monthly/scripts/aggregate.py" <데이터.json> --out /tmp/probe-stats.json
```

프로필이 자동 탐색되고 집계가 통과하면 셋업 완료다. 사용자에게 다음 명령을 안내한다.

```
/ops-report:monthly <데이터.json 경로>
```

이후로는 경로만 입력하면 프로필·베이스라인이 자동으로 잡힌다.
